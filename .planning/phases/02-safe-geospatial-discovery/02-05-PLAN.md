<objective>
Make every target table name deterministic, predictable by inspection, and collision-free before any database work.

Purpose: D-21 is rated one-way — the target table name is the published contract every GIS consumer queries, and Task 2 of plan 02-01 gated it with the operator. This plan makes the rule complete and total: every deviation is a typed closed failure that stops the run before Phase 3 ever opens a connection, and a same-delivery collision is GEO-05's hard stop.
Output: A pure, I/O-free naming module with one validation helper per rule, a version-pinned PostgreSQL keyword snapshot, and a collision detector in the accumulate-and-compare shape `candidates.select_candidate` already uses.

`02-RESEARCH.md` verified against the official PostgreSQL keyword appendix that the classification has four categories and that **two** of them block unquoted use as a table name — not just the one literally labelled reserved. A hand-typed shortlist of "common" reserved words reliably misses the second category. Phase 2 explicitly never opens a database connection, so this check must be a static, version-pinned list embedded in code rather than a runtime keyword query.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| driver-reported layer and dataset names → PostgreSQL identifier | Strings that originated inside an untrusted archive become an identifier a later phase executes DDL with. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-26 | Tampering | `normalize_target_table_name` charset rule | high | mitigate | Only `[a-z0-9_]` survives normalization and every other character is a typed closed failure, so no quote, semicolon, or whitespace from an archive-controlled layer name can reach a later `CREATE TABLE` statement as an injected identifier. |
| T-02-27 | Tampering | reserved-word and leading-digit rules | medium | mitigate | The complete two-category PostgreSQL keyword snapshot plus the leading-digit rule, so no generated name would require quoting to be valid and no name silently changes meaning in a later statement. |
| T-02-28 | Tampering | collision detection | high | mitigate | An exact-equality accumulate-and-compare over one delivery's normalized names, raising before the manifest is built, so two source layers can never be silently collapsed into one published table. |
| T-02-29 | Denial of service | 63-byte limit | low | mitigate | The limit is a typed closed failure rather than a truncation, so no two long source names can be truncated into the same target name. |
| T-02-30 | Elevation of privilege | database access from a pre-mutation phase | high | mitigate | The module performs no I/O and imports no database driver, asserted by an `ast` test, so the phase boundary "before any database mutation" is enforced structurally rather than by convention. |
