Make archive extraction fail closed on every guard, with an adversarial regression for each one.

Purpose: GEO-01 is the phase's security core. The archive arrived over the network in Phase 1 and its central directory is attacker-influenceable metadata. `02-RESEARCH.md` verified by reading CPython 3.14's `zipfile` source that the standard library's own extraction *silently strips* dangerous path components rather than rejecting the member — real behavior, but a silent rewrite, which is exactly the skip-and-continue posture D-26 forbids.
Output: A complete guard chain that rejects before writing anything, ceilings enforced against real decompressed bytes, a single atomic commit point for the run directory, and full member accounting including D-27's companion files.

  <behavior>
    - A member whose raw `filename` begins with `/` or a backslash is `ArchiveTraversalRejected`.
    - A member with any path component equal to two dots, or any component containing a colon (a Windows drive specifier), is `ArchiveTraversalRejected`.
    - A member whose resolved destination is not the run directory itself or a descendant of it is `ArchiveTraversalRejected`, checked after normalizing backslash separators to forward slashes.
    - A member authored on a Unix system (`create_system == 3`) whose `external_attr` upper-16 mode bits are `S_IFLNK` is `ArchiveUnsafeMemberRejected`; so is any mode value other than `0`, `S_IFREG`, or `S_IFDIR`. A member authored on a non-Unix system has its mode bits ignored, because the format only carries Unix mode bits when `create_system == 3` — but its path and regularity checks still run unconditionally.
    - A member with a link count implied by a duplicate `filename` already seen in the same archive is `ArchiveUnsafeMemberRejected`; no member name may appear twice.
    - A member with the encryption bit set in `flag_bits` is `ArchiveUnsafeMemberRejected`.
    - An archive whose member count exceeds `policy.max_member_count` is `ArchiveCeilingExceeded`, decided during validation before any write.
    - Every rejection happens during a complete validation pass over the whole member list, before the first output handle is opened — a valid member appearing before an invalid one is never written to disk.
    - An archive that cannot be opened or whose central directory cannot be read is `ArchiveUnreadable`; no `zipfile` exception text reaches a caller.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| zip central directory → validation | Member names, mode bits, flag bits, and declared sizes are all attacker-influenceable metadata. |
| decompressed stream → local filesystem | The bytes a member actually produces, which may diverge from what it declared. |
| temporary run tree → published run directory | The single commit point that makes a run visible to Phase 3. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-14 | Tampering | `_validate_members` path checks | critical | mitigate | Reject-before-write on raw name, path components, and resolved-path containment; the standard library's bulk and single-member extraction helpers are never called in production code, proven at runtime by a test that makes both raise. |
| T-02-15 | Tampering / Information disclosure | `_validate_members` mode checks | high | mitigate | `create_system == 3`-gated `external_attr` mode-bit inspection rejecting `S_IFLNK` and every non-regular, non-directory mode; duplicate member names rejected so no hardlink-style aliasing survives. |
| T-02-16 | Denial of service | streaming loop | high | mitigate | Per-member and cumulative ceilings tested against actual decompressed bytes before each write, plus a post-member compression-ratio test and a pre-write member-count ceiling. |
| T-02-17 | Tampering | run-directory publication | high | mitigate | One `os.rename` commit point with an explicit existence guard, so a published run directory is never overwritten and no partially written tree is ever visible under a final run-directory name. |
| T-02-18 | Tampering | `verify_artifact` | high | mitigate | Full re-hash and byte-count comparison against Phase 1's recorded values before `zipfile.ZipFile` is constructed. |
| T-02-19 | Denial of service | retained temporary directories | low | accept | D-25 deliberately leaves failed runs on disk for inspection and defers pruning to the backlog; disk growth is managed manually and is not a security control. |
