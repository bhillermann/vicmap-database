<objective>
Make manifest publication atomic, so a reported hard stop leaves nothing behind and a retry can always proceed.

Purpose: closes verification gap 2 (CR-02, GEO-05 blocked) and the adjacent WARNING WR-02. `write_manifest` performs two independent `O_EXCL` creates with no rollback between them. Independently reproduced: with only `manifest.json.sha256` pre-existing, the call raises `ManifestWriteFailed` — the reported hard stop — yet leaves a complete `manifest.json` durably on disk; and because that file was created `O_EXCL`, no retry into that run directory can ever succeed. This directly falsifies 02-06-PLAN.md's own must-have that every GEO-05 hard stop "leaves no `manifest.json` and no manifest sidecar anywhere under the run root," and breaks the immutable half of the phase goal. WR-02 is closed here rather than deferred because it lives in the same function this plan rewrites: `manifest.py` fsyncs each file's own descriptor but never the directory entry, unlike `extraction.py` and `download.py`, which both do.
Output: a publication step that either leaves both files or neither, a durable directory entry once both exist, and regressions that fail the second create specifically — the ordering the existing test suite never reaches.
</objective>

  <action>In `vicmap_acquire/manifest.py`'s `write_manifest`, wrap only the sidecar write in its own `try`, placed after the manifest write has already returned successfully. On an `OSError` from the sidecar write, unlink `manifest_path` on a best-effort basis — a nested `try` swallowing any `OSError` from the unlink itself — then re-raise, letting the existing outer `except OSError: raise ManifestWriteFailed() from None` convert it as it already does. Do not add a new exception type and do not change `write_manifest`'s signature or its return value.

Scope the rollback precisely, because this is the subtle half of the fix. `_write_new_file_fsync` opens with `os.O_WRONLY | os.O_CREAT | os.O_EXCL`, so if the manifest write returns without raising, this call is provably the creator of that file and unlinking it is safe. If `manifest.json` already existed, the *first* create raises `FileExistsError` and control never reaches the sidecar write, so the rollback never runs and a pre-existing manifest is never touched. Do not widen the rollback into a broad handler around both writes — that would let a call unlink a `manifest.json` it did not create, converting the immutability guarantee into a silent overwrite and turning a safety fix into a data-loss bug.

Update `write_manifest`'s docstring to state the publication contract explicitly, the way `download_artifact`'s and `extract_artifact`'s docstrings state theirs: both files are created exclusively and fsynced; a failure after the manifest is created rolls that file back so the call leaves the run directory exactly as it found it; a failed call is therefore always retryable into the same run directory; and an existing complete manifest is still never overwritten.

Extend `tests/test_manifest.py`'s `ManifestRoundTripTest`, reusing its `_manifest()` builder and `make_temp_dir` mixin, with the reproduction and the retry:
  - the reproduction, driven by real filesystem state rather than by mock call ordering: create only `manifest.json.sha256` in a fresh run directory, snapshot `sorted(p.name for p in run_dir.iterdir())`, call `write_manifest`, assert `ManifestWriteFailed`, assert `manifest.json` does not exist, and assert the listing snapshot is unchanged;
  - the retry proof, which is the property the shipped defect made unreachable: patch `os.open` with a side effect that raises `OSError` only on the call that creates the sidecar and delegates to the real `os.open` otherwise, call `write_manifest` and assert `ManifestWriteFailed` with no `manifest.json` left behind, then leave the patch and call `write_manifest` again into that same run directory and assert it returns a digest with both files present and the sidecar matching;
  - the rollback-scope proof: with a complete manifest already published, assert the second call raises `ManifestWriteFailed` and that `manifest.json` is still present and byte-identical, so the rollback provably did not fire;
  - the rollback-failure proof: make the unlink raise and assert the caller still receives `ManifestWriteFailed`.

State in the summary how these would have caught the shipped defect: the existing `test_oserror_translates_to_manifest_write_failed` patches `os.open` globally, so both creates fail identically and the "first committed, second failed" ordering was never reached; the existing `test_existing_manifest_raises_and_leaves_file_untouched` only exercises a failure on the first create. Every new test above targets the ordering between the two creates, which is exactly the axis the suite was blind to.</action>

  <action>Add a module-private `_fsync_directory(directory: Path) -> None` to `vicmap_acquire/manifest.py`, mirroring `vicmap_acquire/extraction.py`'s helper of the same name exactly: `os.open(directory, os.O_RDONLY)`, `os.fsync(descriptor)`, `os.close(descriptor)`, with every `OSError` from opening, syncing, or closing swallowed, because the publish has already committed and this call only strengthens durability and must never re-decide correctness. Keep it a private per-module copy rather than importing from `extraction` or `download`: those two modules already each carry their own private copy, so a third follows the established convention, and `manifest.py` currently imports only from `discovery` — adding a dependency on `extraction` for a durability helper would couple the manifest contract to the extraction module for no contract reason. Call it exactly once, on `run_directory`, after both `manifest.json` and its sidecar have been created successfully and before returning the digest. Do not call it on the rollback path: a call that rolled back has nothing durable to record, and fsyncing there would only obscure that. Placing it after both creates rather than after each one is what makes the durability boundary coincide with the atomicity boundary Task 1 established — the directory entry becomes durable at the same moment the publication becomes complete.

Also assert the file round-trips through `json.loads` with the original strings intact, so canonical serialization is not silently escaping or normalizing them;
  - empty manifest: build a manifest with an empty `layers` tuple and an empty `companions` tuple, publish it, assert `manifest.json` and its sidecar exist with a matching digest, and assert the payload's `layers` and `companions` are both empty JSON arrays rather than absent keys or nulls. Then run the Task 1 reproduction against that same empty manifest — pre-create only the sidecar and assert no `manifest.json` survives — so the rollback path is proven for the degenerate input too;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| failed run → run root | A run reported as a hard stop must leave no artifact a later phase could mistake for a completed handoff. |
| published manifest → Phase 3 | `manifest.json` plus its sidecar is the durable contract Phase 3 builds DDL from; a manifest without its verifying sidecar is unverifiable input. |
| process crash → filesystem durability | A successful return must mean the directory entry survives, not merely that the file contents were flushed. |
