<objective>
Make the shipped configuration able to process the real Vicmap delivery, proven end to end, and stop a plausible letter-case variation from making a delivery invisible.

Purpose: closes verification gap 3. `vicmap.toml` ships `[extraction].max_compression_ratio = 20`, which is below the real delivery's measured per-member ratios, so a real `discover_order.py` invocation hard-stops with `archive_ceiling_exceeded` before discovering any layer. The phase's central deliverable does not work against the data it was built for without a manual config edit first. Both places that already needed this value worked around it with a test-local `200` instead of fixing the shipped file, which is why the whole test suite is green while the product is not.
Output: a recalibrated, evidence-justified shipped ceiling; a live regression that proves the shipped config works rather than proving a private copy of it works; a deterministic regression that fails if the ceiling is ever lowered below the real delivery's worst case; and case-insensitive dataset extension recognition.

Warning disposition (stated explicitly, per the gap scope): `02-VERIFICATION.md`'s WARNING WR-01 (`vicmap_acquire/discovery.py` case-sensitive extension lookup) is CLOSED here in Task 3 — it is a one-expression change plus two regressions and belongs with "the shipped pipeline can process a real delivery shape." The other WARNING, WR-02 (unfsynced manifest directory entries), is CLOSED in plan 02-09 alongside CR-02, because it lives in the same `write_manifest` function that plan already rewrites. Neither warning is deferred.

Requirement scope note: this plan carries `GEO-05` only. The WR-01 fix hardens the GEO-02 discovery path, which `02-VERIFICATION.md` already recorded as SATISFIED; closing an adjacent warning there does not reopen GEO-02 and this plan deliberately does not claim it.
