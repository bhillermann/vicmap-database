<objective>
Profile every discovered layer completely, and prove it against an independent oracle.

Purpose: GEO-03 promises fields, feature count, geometry type, and source CRS, and Phase 3 issues `CREATE TABLE` from exactly that — `String(10)` versus `String(80)` is load-bearing. `02-RESEARCH.md` verified that `pyogrio.read_info()` supplies the count, geometry type, and CRS but *not* field width, precision, or nullability, and that the same GDAL install spells one 3D point geometry three different ways depending on entry point. Both findings are places a hand-written test would share the implementation's blind spot.
Output: Complete dataset enumeration behind the format allowlist, a full per-layer profile combining pyogrio and a read-only `ogrinfo` subprocess, every D-36/D-38/D-39 hard stop, and a differential-oracle test in the established `tests/test_html_visibility_differential.py` style.

Two return values that look similar and must never be conflated (verified against synthetic fixtures during research): `geometry_type is None` is pyogrio's signal for a legitimate geometry-less table, which D-35 discovers **and selects**; `geometry_type == "Unknown"` is the *string* a driver returns for a generic or unresolvable geometry declaration, which D-38 makes a hard stop. Conflating them either wrongly stops a valid lookup table or wrongly accepts an unusable declaration — GEO-05 gets it wrong in both directions.

D-35's flagged consequence is a real branch, not an edge case to defer: Phases 3 and 4 are currently specified around geometry columns, SRIDs, and spatial validation. A geometry-less layer is recorded with an explicit `spatial=False` discriminator rather than leaving the downstream loader to infer intent from a field being null.
</objective>

Research verified against both the real `ADDRESS` layer and a synthetic geodatabase that `ogrinfo -json` emits a `width` key only for `String` fields — OpenFileGDB `Integer`, `Real`, and `DateTime` fields carry neither key, even when the source data was explicitly cast to a specific numeric width and scale. D-37 forbids recording an estimate because this count is the row-count baseline Phase 3's staging validation checks against, so do not substitute an approximation for a slow driver and do not round.

Phase 2 never reprojects; the layer is recorded in its native CRS.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| geodatabase bytes → GDAL/pyogrio | An undocumented Esri binary format inside an untrusted archive, parsed by a large C library. |
| dataset path → `ogrinfo` subprocess | A filesystem path derived from archive member names is handed to an external process. |
| driver-reported metadata → manifest | Geometry type, CRS, counts, and field schema become the contract Phase 3 builds DDL from. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-20 | Tampering | `ogrinfo` invocation | high | mitigate | The command is built as an explicit argument list with no shell, so an archive-controlled path cannot inject arguments or shell metacharacters; the path is already constrained to the run directory by extraction's containment guard. |
| T-02-21 | Denial of service | `ogrinfo` subprocess | medium | mitigate | A configured `ogrinfo_timeout_seconds` bounds every invocation, and `-so` keeps the call off the full-geometry scan path; a timeout is a typed closed failure, not a hang. |
| T-02-22 | Spoofing | format recognition | high | mitigate | The extension-to-driver map is a closed mapping and the driver `read_info()` actually reports is re-checked against the allowlist, so a file whose extension misrepresents its format is still rejected. |
| T-02-23 | Tampering | geometry and CRS metadata | high | mitigate | D-38 and D-39 hard stops on `Unknown` geometry and unresolvable EPSG; no default SRID, no untyped geometry fallback, no reprojection. |
| T-02-24 | Information disclosure | driver error text | medium | mitigate | Every entry point collapses unexpected exceptions to a typed closed failure whose string is its own `code`, so no filesystem path or library diagnostic leaks into operator output. |
| T-02-25 | Tampering | feature count | medium | mitigate | The count is the exact driver-reported integer and becomes Phase 3's row-count baseline; an estimate is never recorded, so a truncated load cannot be masked by an approximate expectation. |
</threat_model>
