# Phase 05.1 Plan 02: Exhaustive fail-closed classification (superseded + ambiguous) Summary

**`order_verdict` gains the D-86 SUPERSEDED outcome and `promotion_result_from_records` gains a single-promotion consistency check, both proven exhaustively offline and live against a real replaced/unmarked table with zero DDL.**

## Performance

- **Duration:** ~25 min

## Accomplishments

- `order_verdict` now returns `SUPERSEDED` when every layer is `RESUMABLE` or `SUPERSEDED` and at least one is `SUPERSEDED` — resolving the D-86 A-vs-D/E conflict for mixed orders the way this plan's objective specifies: a mix of `SUPERSEDED` with `STAGED` or `UNPROVEN` stays `AMBIGUOUS`, because the audit trail itself is inconsistent.
- `classify_publication_state` raises `PublicationSuperseded` (not `PublicationAmbiguous`) for that verdict, before any promotion connection could open — proven live: publish once, rename the published table out of band and create a fresh one under the same name, re-run, and get `pub_generation_superseded` at `db_publish` with the replacement's `(oid, xmin)` unchanged, the old table still present, exactly one publication row, and `summary.json` byte-identical to the first run's.
- `promotion_result_from_records` now enforces single-promotion consistency: every `target_tables` entry must have exactly one row, and the distinct `server_version` and `published_at` values across those rows must each number exactly one (disagreement by a single microsecond is enough to fail closed) — a defensive backstop distinct from `classify_layer`'s own per-layer OID check, since a layer can independently classify `RESUMABLE` while its marker still disagrees with a sibling's.
- `LayerCase` and `classify_layer`'s docstrings now map every member to D-86's lettered cases explicitly, including the `CONFLICTED` edge that D-86 never lettered.
- Five new offline test classes exhaustively table-test `classify_layer` (including the exact-`uint32`-boundary OID comparison) and `order_verdict` (all 13 rows from the plan's behavior spec), prove every ambiguous path opens exactly two read-only connections with no DDL/DML, and mechanically prove via `ast` that a publication marker can only ever be written from inside the promotion transaction.
- Two new live tests join `LivePublishOrderResumeTest` (now 3 tests, none skipped): `test_superseded_generation_fails_closed_without_ddl` (the out-of-band replacement) and `test_unmarked_live_table_fails_closed_as_ambiguous` (the fixture-scale shape of D-88's unmarked `vicmap.vmadd_address`, via a new `staged=False` keyword on `_provision_order_fixture`).
