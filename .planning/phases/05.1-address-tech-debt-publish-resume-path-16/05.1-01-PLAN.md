<objective>
Prove the whole resume path end to end on one layer, then give it a closed vocabulary.

Purpose: WINDOWS.md #16 is a real 2026-09-24 incident: promotion committed, the reader step failed
after commit, and every retry re-entered the promotion, hit `UndefinedTable` on the consumed staging
table, and was misreported as `pub_promotion_failed`. This plan wires the thinnest real fix through
every layer this phase touches: a durable per-layer generation marker in `vicmap_audit.publication`
(D-78..D-82), written inside the promotion transaction; a classification step that runs after the
D-68 gate and before any DDL (D-86, D-89); a resume branch that rebuilds `PromotionResult` from the
durable rows (D-82); and the CLI routed through one seam, `publish.promote_or_resume` (D-83). The
live test reproduces the incident and proves the re-run completes (D-93). Task 2 then registers the
closed vocabulary every later plan raises (D-87, D-90, D-91) and the progress event D-84 needs.

Output: the provisioned marker table, the marker write, the classifier core, the resume seam, the
new evidence vocabulary, and the live `LivePublishOrderResumeTest`.

Planner decisions recorded here (Claude's Discretion in CONTEXT.md):
- The classify-then-branch composition lives in `publish.promote_or_resume` (gate, classify, then
  promote or resume), which `publish_order.main` calls as its single publication seam. `promote_order`
  keeps its exact signature and its own gate, so it stays safe to call standalone (T-04-06). This
  follows CONTEXT's integration hint (classification after the gate, before promotion) without
  running the gate twice.
- Marker columns: `run_ts text`, `manifest_digest text`, `target_table text`, `table_oid oid`
  (PostgreSQL `oid`, never `integer`, so no OID above 2^31-1 can overflow), `server_version text`,
  `published_at timestamptz`, and `recorded_at timestamptz DEFAULT now()` for parity with
  `staging_validation`. Primary key `(run_ts, manifest_digest, target_table)` (D-80).
- Research Open Question 1: `Stage.PUBLICATION_SUMMARY = "publication_summary"` is added. The shared
  string is safe because `stage` is a field of failure lines (whose `event` is always `failure`),
  while `publication_summary` as an `event` value appears only on the success line.
</objective>
