<objective>
Report every vicmap_audit read failure at its true boundary, and prove `pub_promotion_failed` can
only come from the promotion transaction.

Purpose: D-90 requires every vicmap_audit read (the gate, resume detection, and
`read_layer_validations`) to report at `db_audit`, never `pub_promotion_failed`. D-92 confines
`pub_promotion_failed` to the promotion transaction itself. Plan 05.1-01 already put classification
on the audit-read connection. The D-68 gate and `read_layer_validations` still use the
promotion-mapping `_connect`, the same defect class as WINDOWS.md #16 one level up (RESEARCH
Pitfall 2). This plan moves both, then pins the boundary mechanically.

Output: gate and validation re-read on `_connect_for_audit_read`, a marker-privilege precheck on
promote verdicts, and an AST-level proof of the D-92 boundary.

Planner decisions recorded here:
- The D-68 gate also moves off `_connect`. RESEARCH Pitfall 2's warning-sign line kept `_connect` in
  the gate, but D-92 is explicit that pub_promotion_failed comes only from inside the promotion
  transaction, and the gate is a vicmap_audit read (D-90).
- Research Open Question 2: `staging.preflight_staging_privileges` is not extended. The staging CLI
  never touches the publication table, and `staging_validation` set that precedent. Instead, the
  publish-side classification is the pre-DDL check for the marker table. Its SELECT proves read
  access (InsufficientPrivilege becomes db_audit_privilege_denied), and on a promote verdict an
  explicit INSERT privilege check fails closed with db_audit_privilege_denied, whose hint points at
  the provisioning script. Without it, a missing grant would only surface as a rolled-back
  pub_promotion_failed.
</objective>
