<objective>
Replace the flat suppression counter with a real HTML5 parse tree, and lock the result in place with a differential test against a spec-compliant oracle.

Purpose: The counter model has been defeated four times (the 01-12 outage, CR-01, CR-02, and a fourth report that turned out to be a false positive). A differential fuzz over 4,000 generated documents shows the true scale: 287 disagreements with a spec parser, 146 of them in the leak direction — content our code collects that a mail reader would not display. Targeted fixes do not converge on that, because the tests and the implementation share the same blind spot. Only an independent oracle exposes it.
Output: Tree-based visibility, a permanent differential test, and a verified-unchanged result against the real ready message.
</objective>

## Evidence, measured by the orchestrator

Differential fuzz, seed `20260914`, 4,000 generated documents built from a fixed vocabulary of open tags, close tags, self-closing forms, void elements and comments, with an archive URL or an anchor carrying one inserted at a random position:

```
disagreements: 287 / 4000
  leaks   (we collect what a spec parser says is hidden):  146
  strands (we hide what a spec parser says is shown):      141
```

Sixteen handpicked shapes — including every shape named in 01-REVIEW-GAP-CLOSURE.md and 01-VERIFICATION.md — all agreed. That is the point: handpicked cases share the implementation's blind spot, so they cannot find this class. The oracle can.

A note on the fourth reported bypass, so the record is accurate: `01-VERIFICATION.md` reports a nested-`<body>`-in-`<template>` shape as a leak. It is not one. A spec parser relocates that `<template>` into `<body>`, making the following text genuinely rendered, so collecting it was correct. The finding was a false positive; the underlying structural claim it was offered in support of is nonetheless true, and is what this plan closes.

## Supply-chain disposition

Recorded legitimacy evidence: `html5lib` is supplied by `nixpkgs` through the project's existing pinned flake input, its source hash is verified by Nix at build time, and it enters the same `python3.withPackages` environment as the already-trusted `python-o365`. No `pip`, `npm` or `cargo` install occurs at any point. This preserves the posture the phase's other threat models assert.

<task type="auto" tdd="true">
  <name>Task 2: Decide rendered visibility from a parse tree</name>
  <files>vicmap_acquire/candidates.py, tests/test_candidates.py</files>
  <read_first>
    - vicmap_acquire/candidates.py (`_NON_RENDERED`, `_VOID_ELEMENTS`, `_AnchorCollector`, `_extract_html_urls`, `extract_html_hrefs`)
    - .planning/phases/01-trusted-graph-acquisition/01-13-SUMMARY.md (the counter model being replaced, and why its one-shot body decrement existed)
  </read_first>
  <behavior>
    - An archive URL inside `script`, `style`, `template`, `noscript`, `title`, `object`, `applet` or `iframe` content yields no archive link.
    - An archive URL inside an HTML comment yields no archive link.
    - An archive URL in ordinary visible body text yields exactly one archive link.
    - An `a` element's `href` in rendered context yields exactly one archive link.
    - A document whose `<head>` is never closed still yields the archive link from its body.
    - Self-closing syntax on a non-void element does not expose the content after it.
    - Collection order is preserved exactly as 01-07 specified: anchors in document order, then rendered-text occurrences in document order.
  </behavior>
  <action>
Replace `_AnchorCollector` and its counter with an `html5lib`-based implementation.

Parse with `html5lib.parse(content, namespaceHTMLElements=False)` to get an ElementTree. Define `_HIDDEN_ELEMENTS = frozenset({"script", "style", "template", "noscript", "title", "object", "applet", "iframe", "head"})`. Walk the tree from the root, carrying a `hidden` flag that is inherited by every descendant: a node is hidden if its parent chain was hidden, or its own tag is in `_HIDDEN_ELEMENTS`. This inheritance is the whole point — it is what a depth counter could only approximate.

Collect, only from non-hidden nodes:
- an `a` element's `href` attribute, and
- element `text` and `tail` character data, routed through the existing `extract_text_urls`.

Handle these tree details explicitly, because each one is a way to reintroduce the bug:
- A comment node's `tag` is not a string. Skip its content, but still process its `tail`, which belongs to the parent's flow and is rendered.
- A node's `tail` belongs to its PARENT's visibility, not its own. Text after `</script>` is rendered even though the script is not.
- `head` stays in the hidden set. The parser now decides what is actually inside `head`, which is what makes the 01-13 one-shot `<body>` decrement unnecessary — delete that special case rather than porting it.

Keep `extract_text_urls`, `_archive_order_id`, `_archive_links`, `_mime_archive_links`, `recognize_candidate` and `select_candidate` behaviourally unchanged. The plain-text-first / HTML-fallback rule (D-04), the exactly-one-link rule (D-05), and the deliberate non-deduplication of repeated identical URLs all stay exactly as committed.

`extract_html_hrefs` remains public and must still return anchor hrefs in rendered context only. Keep its docstring accurate.

Delete `_NON_RENDERED`, `_VOID_ELEMENTS` and `_AnchorCollector` once nothing references them. Do not leave the old path in place behind a flag — two extraction models is how the guarantees drift apart again.
  </action>

  <behavior>
    - A seeded generator builds documents from open tags, close tags, self-closing forms, void elements and comments, inserting an archive URL or an anchor carrying one at a random position.
    - For each document, extraction is compared against an independently written oracle walk over the `html5lib` tree.
    - The test fails on ANY leak-direction disagreement — a URL our code collects that the oracle says is hidden.
    - The seed is fixed so the suite is deterministic and a failure is reproducible from the seed alone.
    - The failure message prints the offending document, so a regression is diagnosable without rerunning the fuzzer by hand.
  </behavior>
  <action>
Write `tests/test_html_visibility_differential.py`.

The oracle must be written independently of the implementation — a separate walk expressing "what would a reader see", not a call into `candidates.py` internals. If the oracle simply calls the code under test, the test proves nothing. This is the single most important property of this file; state it in a module docstring so a future editor does not casually refactor the two into one helper.

Use at least 2,000 documents with seed `20260914`. Assert zero leak-direction disagreements.

Treat strand-direction disagreements (we hide what the oracle shows) as a reported warning rather than a hard failure, and assert only that the count does not exceed a recorded baseline you measure and write into the test as a named constant with a comment explaining it. Strands fail closed — they reject a message rather than accept a bad one — so they are a correctness concern, not a security one, and holding them at a measured baseline prevents silent drift without blocking on shapes no real sender emits.

Keep the runtime reasonable. If 2,000 documents makes the suite noticeably slow, reduce the count but never below 1,000, and say in the summary what you chose and what it cost.
  </action>
