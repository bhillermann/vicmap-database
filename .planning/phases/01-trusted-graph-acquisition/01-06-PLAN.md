<objective>
Prove one production-quality end-to-end slice in which artifact authenticity is established, not merely label-matched: the trusted receiving mail infrastructure's DKIM verdict binds the message to the configured sender domain, and an exact configured URL prefix binds the artifact target to the trusted bucket/path authority on the already-allowlisted host.

Purpose: Close verification gap G-01 bullets 1-3. Phase 01 verification found that the trust chain accepted the provider `From` value, exact subject/filename text, and any path on the shared `s3.ap-southeast-2.amazonaws.com` authority, so the word "authentic" in the phase goal was not achieved.
Output: A new `vicmap_acquire/origin.py` policy module, a URL-prefix authority constraint applied to every hop, two new non-secret policy keys, and end-to-end positive and negative proof.

Chosen authority signal and why: Vicmap DataShare publishes no artifact signature and no out-of-band digest, so the only cryptographically grounded origin signal reachable from this phase's data is the DKIM/DMARC verdict recorded by Microsoft 365 in the message's `Authentication-Results` headers, which this project already trusts for mailbox access itself. That verdict is combined with an exact bucket/path prefix so the artifact must live inside the sender's own object authority. Together these replace "matching untrusted labels on a shared host".
</objective>
