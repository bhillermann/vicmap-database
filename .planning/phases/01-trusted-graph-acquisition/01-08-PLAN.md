<objective>
Give the downloader an explicit publication commit point so a handled finalization failure can never leave a published final artifact and a private partial while reporting failure.

Purpose: Close verification gap G-03. Output: Commit-point-separated finalization, the injected post-link cleanup regression, and the redirect-prefix and MAIL-04/MAIL-05 edge regressions.
</objective>

  <action>
Restructure the tail of `download_artifact` so publication is a named, single commit point rather than a statement inside the transfer failure region.

Add `temp_cleanup_deferred: bool = False` to `DownloadResult`, keeping it last so existing keyword and positional construction in tests continues to work.

Add `_fsync_directory(directory: Path) -> None` which opens the directory with `os.open(directory, os.O_RDONLY)`, calls `os.fsync` on the descriptor, and closes it, swallowing `OSError` only for platforms where directory fsync is unsupported. Call it immediately after a successful `os.link`, before constructing the result, so a returned success establishes directory-entry durability.

Add `_publish_artifact(temp_path: Path, final_path: Path) -> bool`. It performs `os.link(temp_path, final_path)`; a `FileExistsError` propagates so the caller can translate it to `ArtifactWriteFailed`, preserving the existing no-overwrite guarantee and the concurrent-winner semantics. After the link succeeds, it calls `_fsync_directory(final_path.parent)`, then attempts `temp_path.unlink()` inside its own `try` that catches `OSError` only, and returns `True` when cleanup succeeded and `False` when it did not. No exception raised by cleanup may leave this function.

In `download_artifact`, the commit boundary is the successful return of `_publish_artifact`. Before it, every failure keeps today's behaviour. After it, set `temp_path = None` unconditionally so the outer `finally` does not attempt a second unlink of a name this function has already decided about, and construct and return the `DownloadResult` with `temp_cleanup_deferred` set to the negation of `_publish_artifact`'s return value.

The `except OSError: raise ArtifactWriteFailed() from None` handler must therefore no longer be reachable from post-commit cleanup. Achieve this by calling `_publish_artifact` such that its only escaping exception is `FileExistsError`, translated to `ArtifactWriteFailed` exactly as today.

Keep the existing `finally` block, including `_close(response)`, the guarded `temp_path.unlink()` for the pre-commit paths, and `_close(session)`. Its unlink attempt must remain guarded and must remain a no-op once `temp_path` has been set to `None`.

Do not change `format_progress`, `validate_https_target`, `_request_final_response`, timeout handling, or the byte-ceiling comparisons in this task.

Record the durability and cleanup semantics in the `download_artifact` docstring so the commit point is discoverable from the source rather than only from this plan.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTPS redirect chain → next request | Each `Location` value is remote-controlled input that must be re-authorized before contact |
| HTTPS stream → filesystem | Bounded bytes crossing into private temporary state and then into a published final path |
| Graph environment → artifact session | Ambient credentials, cookies, proxies, and netrc must not cross this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
