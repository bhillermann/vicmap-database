## RESEARCH correction to a locked decision — D-50 (`proj-data`) does not exist

**This is a plan-visible correction, not a silent override.** CONTEXT.md D-50 states
"`proj-data` joins `flake.nix`". `03-RESEARCH.md` Common Pitfall 1 reports, with evidence, that
this cannot be done as written:

| Claim in D-50 | What research found | Evidence cited in 03-RESEARCH.md |
|---|---|---|
| `proj-data` is a nixpkgs package | It is not a top-level nixpkgs attribute at the flake's pinned revision. `proj`, `proj-datumgrid`, and `proj_7` are the only `proj*` matches. | `nix eval` over nixpkgs top-level attribute names, this research session |
| The similarly-named `proj-datumgrid` would do | It builds to a ~16.5 KiB output containing only the `nad2bin` format-conversion binary, with no grid data | `nix build` + `find` on the resulting store path |
| PROJ ships the grids | PROJ ≥ 7 (2020) split grid data out of the main distribution; the pinned `proj` 9.8.1 `share/proj` has `proj.db` and 15 other entries and zero `.tif`/`.gsb` files | D-50's own measurement, corroborated by research |

D-50's **goal** — get the ICSM GDA94↔GDA2020 NTv2 grid onto disk so PROJ stops silently
ballparking a 1.56 m error — is unchanged and still correct. Only the mechanism must change.
Task 2 puts that choice in front of the operator rather than picking one silently.
