## Flagged planner assumptions (spec-less edge probe, DB-04)

The deterministic edge probe classified `DB-04` as **`unclassified`**. An unclassified row is
never auto-resolved with a backstop, so it is carried here as an explicit flagged assumption.

| Requirement | Probe status | Planner assumption being made |
|---|---|---|
| DB-04 | `unclassified` — **UNRESOLVED, flagged** | Three judgments this plan makes that CONTEXT.md does not settle. (a) A `NULL` geometry in a spatial layer is treated as a blocking `GeometryTypeMismatch`, because D-63 requires `NOT NULL` on the geometry column before promotion and a `NULL` would otherwise surface as a raw `ALTER` error in 03-06. (b) A spatial layer holding more than one distinct SRID or more than one distinct geometry type is blocking, not just a wrong single value — the queries use `LIMIT 2` on a `DISTINCT` to detect the mixed case. (c) A repair that leaves a row still invalid is blocking (`GeometryRepairIncomplete`); D-54 says invalid geometries are repaired rather than blocking, but is silent on a repair that does not succeed. If the operator intends any of these three to be reported rather than fatal, the assumption is wrong. |

## Deviation from 03-VALIDATION.md's Wave 0 list — surfaced, not silent

`03-VALIDATION.md` lists a Wave 0 requirement for "a small deliberately-invalid-geometry
fixture (bowtie polygon or self-intersecting line) loadable via `ogr2ogr`". **This plan does not
build that fixture, and that is a deliberate change the reader should see.**

D-53 states validation runs against the staging table in PostGIS, after reprojection — not
against the source file. The subject under test is therefore a *table*, and the shortest honest
way to give it known-invalid content is to `INSERT` known WKT directly into a throwaway table in
the live-test fixture. That avoids (a) checking a new ~megabyte binary into the repository,
(b) depending on the OpenFileGDB writer to round-trip a deliberately invalid geometry unchanged,
and (c) guessing at plan time which invalid geometry `ST_MakeValid` will repair type-preserving
versus type-changing — the tests below determine that at runtime from the live server rather
than from a planner's recollection.

The end-to-end path through `ogr2ogr` is still covered: 03-04's `LoadIntegrationTest` loads the
real `Order_TRACER1.zip` fixture. What is replaced is only the mechanism for producing invalid
geometry, not the coverage.

  <action>Every part of validation that can be decided without a database goes into a pure function here, so DB-04 has real automated coverage on a machine with no PostgreSQL server. Only the execution belongs in Task 2.

**`normalize_declared_geometry_type(declared)`.** `LayerProfile.geometry_type` carries `pyogrio`'s vocabulary — `Point`, `Point Z`, `MultiPolygon`, `LineString ZM` and so on, verified during Phase 2 (`tests/fixtures/point_z_gdb.zip` exists specifically because `read_info()` reports the exact string `Point Z`). PostGIS reports the same geometry two different ways: `GeometryType(geom)` returns an uppercase name with the dimension suffix attached and no space (`POINTZ`), and `ST_Zmflag(geom)` returns an integer. Map between them by splitting the declared value on whitespace: the first token uppercased is the base name, and any remaining token must be exactly `Z`, `M`, or `ZM`, looked up in `_ZM_SUFFIX_FLAGS = {"": 0, "M": 1, "Z": 2, "ZM": 3}`. Return `(base + suffix, flag)`. Raise `GeometryTypeMismatch` for an empty value, a `None`, a base name that is not one of the seven OGC names `POINT`, `LINESTRING`, `POLYGON`, `MULTIPOINT`, `MULTILINESTRING`, `MULTIPOLYGON`, `GEOMETRYCOLLECTION`, or a suffix token outside the three allowed. Do not accept `Unknown` — Phase 2's D-38 already hard-stops on it, and silently accepting it here would reopen that gap.

**`build_validation_query(*, staging_schema, staging_table, spatial)`.** Compose with `psycopg.sql.SQL` and `psycopg.sql.Identifier(staging_schema, staging_table)` — never an f-string. Return one read-only query per profile.

For `spatial=False` (D-57's non-spatial profile), the query selects the row count and nothing else. It must contain no `ST_` call and no reference to a geometry column at all: D-35's lookup tables and relationship classes have no geometry, and `NONE_AS_UNKNOWN` defaults to `NO`, so the staging table genuinely has no geometry column to query.

For `spatial=True`, one query computes every fact in a single pass over the table, because the 4.2M-row `ADDRESS` layer makes each extra sequential scan expensive. Follow 03-RESEARCH.md's Architecture Pattern 3 shape and return these columns:
   - `row_count` — `COUNT(*)`.
   - `null_geom_count` — `COUNT(*) FILTER (WHERE geom IS NULL)`.
   - `invalid_count` — `COUNT(*) FILTER (WHERE NOT ST_IsValid(geom))`.
   - `type_changed_count` — `COUNT(*) FILTER (WHERE NOT ST_IsValid(geom) AND GeometryType(ST_MakeValid(geom)) IS DISTINCT FROM GeometryType(geom))`. Computing this *before* any write is what makes D-55 a hard stop rather than a post-mortem: the research note is explicit that the `UPDATE` may only run once this is zero.
   - `srids_seen` — an aggregated array of `DISTINCT ST_SRID(geom)` capped at two elements, so a table holding two different SRIDs is distinguishable from one holding a single wrong SRID.
   - `geometry_types_seen` — the same two-element cap over `DISTINCT GeometryType(geom)`.
   - `zmflags_seen` — the same two-element cap over `DISTINCT ST_Zmflag(geom)`.
   - `extent` — `ST_Extent(geom)`, cast to text or returned as a box; the caller parses it into the four floats `LayerValidation.extent` holds.
   Use a lateral or scalar-subquery form for the capped distinct sets rather than `DISTINCT ... LIMIT 2` as a bare select column, which is not valid in that position.

**`build_repair_statement(*, staging_schema, staging_table)`.** Returns the composed `UPDATE <table> SET geom = ST_MakeValid(geom) WHERE NOT ST_IsValid(geom)`. Also pure, also `sql.Identifier`-composed. D-54 chose `ST_MakeValid` over any hand-rolled repair, and D-55 explicitly rejected `ST_CollectionExtract` salvage because it discards geometry silently — do not add either.

Add two non-live test classes to `tests/test_staging.py`. Neither may skip.
