sequentially in manifest order with named diagnostics, and prove production is untouched when
something fails.

Purpose: A validated table is not yet a table Phase 4 can promote. D-63 names three things

DB-05's guarantee, meanwhile, is only a guarantee if something actually checks it.

orchestration with per-layer progress, the named stderr diagnostic file, and the induced-failure
isolation proof.

never auto-resolved with a backstop, so it is carried here as an explicit flagged assumption.

| Requirement | Probe status | Planner assumption being made |
|---|---|---|
| DB-05 | `unclassified` — **UNRESOLVED, flagged** | Assumed that "existing production tables" means every table outside `vicmap_staging` — that is, everything in `public`, everything in the publish schema, and everything in any other schema on the server — and that "unchanged" is provable by comparing a `pg_class`/`pg_tables` catalog snapshot plus a per-table row count before and after an induced failure. ## Open Question 1 is settled here, empirically, not by assumption

`03-RESEARCH.md` could not determine whether GDAL's PostgreSQL driver already creates a typed
`geometry(Type, SRID)` column when the layer's geometry type and `-t_srs` are both known, or
whether it always creates a bare `geometry` column. Research Common Pitfall 2 recommends not
hard-coding either answer. This plan therefore reads the column's actual type from
`geometry_columns` before deciding whether an `ALTER` is needed, and Task 1 records the observed
answer in the SUMMARY so the question stops being open.

Steps, in this order, all inside one transaction that commits at the end and rolls back on any failure. Any `psycopg` error raises the closed `StagingDdlFailed` with no driver text.

1. **Primary key on `gid` (D-63).** Add it unconditionally: `ALTER TABLE <staging_table> ADD PRIMARY KEY (gid)`. QGIS needs a unique integer column to load a table as a proper editable layer, and `-lco FID=gid` gave it one. If GDAL already created the column as the table's primary key, adding a second raises — so check `pg_index`/`pg_constraint` for an existing primary key on the table first and skip the statement when one exists, recording which branch was taken.

2. **Typed geometry column with its SRID (D-63) — conditionally.** This is research Open Question 1 and Common Pitfall 2, and the answer must be read, not assumed. Query `geometry_columns` for this table's `geom` entry and compare its `type` and `srid` against the declared type from `normalize_declared_geometry_type(manifest_layer.profile.geometry_type)` and `policy.target_srid`:
   - Already typed and matching → record that GDAL created the typed column itself and issue no `ALTER`.
   - Bare `geometry`, or typed with the wrong parameters → issue `ALTER TABLE <t> ALTER COLUMN geom TYPE geometry(<Type>, <srid>) USING geom`. PostgreSQL's `ALTER TYPE` semantics make the cast a no-op when the type already matches, so the `USING` clause is safe either way; the conditional exists to keep the SUMMARY's answer to Open Question 1 honest, not because the statement is unsafe.
   - Neither branch may proceed if the observed type disagrees with what `validate_layer` just asserted — that would mean the two read different things, so raise `StagingDdlFailed`.
   Record the observed pre-`ALTER` column type in the return value and in the SUMMARY. **That recorded observation is this phase's answer to research Open Question 1.**

3. **`NOT NULL` on the geometry column (D-63).** `ALTER TABLE <t> ALTER COLUMN geom SET NOT NULL`. 03-05 already proved no row holds a `NULL` geometry, so this cannot fail for data reasons; it exists so the constraint is part of the published contract rather than a fact that happened to be true once.

4. **GiST index (D-62).** `CREATE INDEX <name> ON <t> USING GIST (geom)`, built now, once, over the populated table. Name it deterministically from the staging table — the same name shape every run, so the index name is predictable for Phase 4. Do not use `CONCURRENTLY`: it cannot run inside a transaction block, and there is no concurrent reader to protect here.

5. **Secondary btree indexes from the allowlist (D-64).** For each entry in `policy.index_columns`, create `CREATE INDEX <name> ON <t> (<column>)` **only if** the manifest layer actually declares a field that launders to that column name. Determine "launders to" from `manifest_layer.profile.fields`: GDAL's `LAUNDER=YES` lowercases and launders, so compare each field's name casefolded against the allowlist entry. A table declaring none of the allowlisted columns gains no secondary index and nothing fails — D-64 is explicit that this is the correct outcome, not a warning. Do not consult `information_schema` to discover columns; the manifest is the declaration of record, and using it keeps this decision reproducible from the frozen input.

**Non-spatial layers.** Steps 2, 3 and 4 do not apply — a D-35 lookup table has no geometry column and `NONE_AS_UNKNOWN` defaults to `NO`, so the staging table genuinely has none. Apply step 1 and step 5 only, and return a result naming just what was created. Branch on `validation.spatial`, the same boolean the validation profile used, so the two can never disagree.

Return the tuple of created constraint and index names in creation order.
