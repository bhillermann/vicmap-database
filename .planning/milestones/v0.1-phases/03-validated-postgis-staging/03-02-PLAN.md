<objective>
Make the database boundary reviewable in `vicmap.toml` and enforce its contract in one place.

Purpose: Every value the loader needs — which server, which schemas, which SRID, which columns
get a secondary index, how long a statement may run — is policy, not code. D-58 keeps all of it
in the one file that already holds every other non-secret policy value, and keeps the password
out of it entirely. Getting this contract wrong later means changing a published schema name
after Phase 4 has published against it.
Output: A fifth `[database]` section, a `DatabaseRunConfig` the loader consumes, one validator
that both the TOML loader and a directly constructed config must pass, and the Phase 3 test
module.

This plan opens no connection and imports no database driver. It is pure policy.
</objective>

<assumption_delta_decision>
**Kind:** `chosen` — a derived value became a configured one.

**What changed:** Phase 2's D-39 *derived* each table's SRID from its own source layer's native
CRS and forbade reprojection. Phase 3's D-49 supersedes that: the SRID is now *chosen* once, as
`[database].target_srid`, and every layer is reprojected to it.

**The question:** has a configuration decision become a modeling decision? **Yes.** The SRID is
baked into every staging geometry column (D-63's `geometry(Point, 7899)`) and, after Phase 4,
into every published column and every downstream QGIS project. It is no longer a knob; it is the
estate's single spatial reference.

**Noun that is now primary:** the **estate's target SRID**, not the source layer's native CRS.

**Decision: `promote`.** `target_srid` is promoted to the primary spatial reference for every
staging and published table. `LayerProfile.epsg` — Phase 2's per-layer native EPSG — is demoted
to a per-layer detail whose only remaining job is to be the transform's input, and D-39's hard
stop on an unresolvable EPSG survives precisely because the transform requires it. This is a
promote, not an add-alongside: there is no code path in this phase that writes a table in any
SRID other than `target_srid`, and D-56 makes a mismatch a blocking validation failure.

**Suggested (not required) invariant test:** a contract test asserting that for a manifest whose
layers declare two different `epsg` values, every resulting staging table reports the same
`ST_SRID`. 03-05 Task 2's SRID check is the natural home.
</assumption_delta_decision>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-06 | Tampering | `[database]` identifier values reaching SQL | high | mitigate | `_PG_IDENTIFIER` fullmatch (`[a-z][a-z0-9_]{0,62}`) on `dbname`, `user`, both schema names, and every `index_columns` entry, validated before any connection exists.
