## Reproductions, confirmed by the orchestrator

Run against the committed pipeline entry point, not a reconstruction. `URL` is a well-formed archive URL inside the configured trusted prefix.

CR-01 — self-closing syntax on a non-void element lets suppressed content escape:

```
<script src="x"/>      -> urls=1 archive_links=1   LEAK
<style/>               -> urls=1 archive_links=1   LEAK
<head/>                -> urls=1 archive_links=1   LEAK
<noscript/>            -> urls=1 archive_links=1   LEAK
<template/>            -> urls=1 archive_links=1   LEAK
control: <script src="x">URL</script>  -> archive_links=0   (correctly suppressed)
```

HTML5 ignores a trailing `/` on a non-void element: the element stays open and swallows what follows. `handle_startendtag` currently treats it as opened-then-closed, so the following text is collected as visible. A mail reader would never display it.

CR-02 — an omitted end tag strands suppression permanently:

```
<html><head><meta charset='utf-8'><body><p>URL</p></body></html>
  -> urls=0 archive_links=0    body silenced
control, </head> present       -> archive_links=1
```

Every real HTML5 parser implicitly closes `<head>` when body content begins. This tokenizer does not, so the counter never comes down — the 01-12 outage, reached a different way.

In `_AnchorCollector.handle_startendtag`, stop treating self-closing syntax as a close for non-void elements. HTML5 ignores a trailing `/` on any non-void element, so the correct model is:

- Otherwise: route it to `handle_starttag` ONLY. Do not call `handle_endtag`. A non-void element written with self-closing syntax is an open tag, so if it is in `_NON_RENDERED` the counter must rise and stay risen until a real end tag arrives.

This is a behaviour change in the safe direction: content that a mail reader would not render stops being collected. It must not change what happens to any properly closed element.

  <action>
Model implicit closure for `head` specifically, which is the only element in `_NON_RENDERED` that real senders routinely leave unclosed and that HTML5 closes implicitly.

Take the narrower of these two approaches, and state in the summary which you took and why:

(a) Remove `head` from `_NON_RENDERED` and rely on its meaningful children being suppressed in their own right — `title`, `style`, `script`, `template` and `noscript` are all already in the set, and `meta`/`link` are void and collect nothing. (b) Keep `head` in `_NON_RENDERED` but treat a `<body>` start tag as implicitly closing it, decrementing the head's contribution.

Prefer (a) unless a regression shows it loses a guarantee. It removes a whole class of fragility rather than adding a special case, and every behaviour in this task's `<behavior>` list is carried by an element other than `head` itself.

Do NOT generalise implicit closure to `script`, `style`, `template` or `noscript`. An unclosed `script` genuinely does swallow the remainder of the document in a real parser, so its strand is correct behaviour and removing it would reopen CR-01's class.
