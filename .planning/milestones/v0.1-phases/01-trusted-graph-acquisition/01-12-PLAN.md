<objective>
Stop non-rendered suppression from leaking past the document head, so a genuine Vicmap DataShare ready message can be recognized again.

Purpose: Close a defect introduced by plan 01-07 and confirmed against live mail during 01-11 Task 2. `_NON_RENDERED` contains the void elements `meta` and `link`, which emit no end tag. `handle_starttag` increments `non_rendered_depth` for them and nothing ever decrements it, so after a typical email `<head>` the counter stays permanently raised and the entire body is suppressed. 01-11's single permitted live invocation closed with `candidate_ambiguous` for exactly this reason.
Output: Void-element-safe suppression, plus regressions built from realistic email head markup rather than the synthetic self-closing form that let the defect through.
</objective>

## Evidence from the live message

Tracing `_AnchorCollector` over the actual ready message for order `OK0VUZ` (70,625 characters of HTML, no plain-text part) produced this counter trace, recorded here so the fix is verified against the real failure rather than a reconstruction:

```
head→1  meta→2  meta→3  meta→4  meta→5  link→6  link→7  link→8  link→9
style→10  /style→9  meta→10  meta→11  /head→10
final depth after parse: 10        (never returns to 0)
anchors seen, suppression depth at each: [10, 10, 10, 10]
```

Only `style` and `head` ever paired with an end tag. The six bare `<meta>` and three bare `<link>` tags each raised the counter permanently. All four body anchors were suppressed, and `handle_data` suppressed the visible body text in which the archive URL actually appears — it sits in ordinary `p`/`span`/`strong` content, governed by no attribute.

With void elements excluded from the counter, the same message yields `final depth: 0`, one href URL, three visible-text URLs, and exactly one archive link whose order id is `OK0VUZ` and which matches the configured trusted prefix.

## Why 01-07's suite stayed green

01-07's plan text anticipated the void-element hazard but placed the compensating decrement only in `handle_startendtag`, which Python's `HTMLParser` invokes solely for the XHTML self-closing spelling `<meta />`. Its tests used that spelling. The bare `<meta ...>` spelling that real email uses routes to `handle_starttag`, which has no such compensation. The regressions in Task 2 therefore use bare-spelling head markup; a fix verified only against self-closing markup would not have caught this and must not be accepted as sufficient.

  <action>
In `vicmap_acquire/candidates.py`, introduce a module constant naming the HTML void elements: `_VOID_ELEMENTS = frozenset({"area", "base", "br", "col", "embed", "hr", "img", "input", "link", "meta", "param", "source", "track", "wbr"})`.

A void element cannot contain anything, so it can never suppress content. Make that the single rule and apply it uniformly:

- In `handle_starttag`, treat a tag as suppression-raising only when it is in `_NON_RENDERED` **and not** in `_VOID_ELEMENTS`. A void element named in `_NON_RENDERED` must fall through without touching the counter and without collecting an href — it is neither a container nor an anchor.
- In `handle_endtag`, apply the same combined test before decrementing, so a stray `</meta>` cannot lower the counter and let suppressed content escape. Keep the existing clamp at zero.
- In `handle_startendtag`, the increment-then-decrement dance for `_NON_RENDERED` tags becomes unnecessary for void elements and wrong for nothing: route the tag through the same combined test so both spellings of `<meta>` behave identically.

Keep `meta` and `link` in `_NON_RENDERED`. Removing them would be the wrong repair: the set records which elements are non-rendered, which remains true, and the `_VOID_ELEMENTS` test is what encodes that a non-rendered void element has no contents to suppress. Leaving both facts explicit keeps the two concerns separable.

Do not change `extract_text_urls`, `_archive_order_id`, `_archive_links`, `_mime_archive_links`, `recognize_candidate`, or `select_candidate`. The plain-text-first / HTML-fallback rule (D-04), the exactly-one-link rule (D-05), and the deliberate non-deduplication of repeated identical URLs all stay exactly as committed — this plan repairs suppression only, and must not make recognition more permissive in any other respect.
