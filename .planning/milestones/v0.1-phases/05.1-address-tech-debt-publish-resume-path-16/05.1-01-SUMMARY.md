# Phase 05.1 Plan 01: Publish resume path (durable markers + closed vocabulary) Summary

**A durable `vicmap_audit.publication` marker, written inside the promotion transaction, lets `publish_order.py` classify and resume a committed-but-incomplete publish instead of re-entering promotion and hitting `UndefinedTable` — proven live against the reproduced 2026-09-24 incident.**

## Performance

- **Duration:** ~90 min
- **Completed:** 2026-09-29T04:11:25Z
- **Tasks:** 2 completed
- **Files modified:** 7

## Accomplishments

- `vicmap_audit.publication` (D-78) is a new by-hand provisioned, superuser-owned table (`db/provision_vicmap_loader.sql`) recording one row per `(run_ts, manifest_digest, target_table)`, with `vicmap_loader` granted `SELECT, INSERT` only.
- `promote_order`'s transaction now writes that marker immediately after each layer's rename/grant, capturing the published table's `pg_class` OID server-side via the INSERT's own subquery — never round-tripped through Python (D-79/D-81/D-82).
- A new pre-DDL classifier (`classify_layer`, `order_verdict`, `classify_publication_state`) reads the marker plus live `pg_class` state on a distinct, read-only, repeatable-read connection (`_connect_for_audit_read`) whose own connect/setup failures map to the new `AuditReadFailed`, never `PromotionFailed` (D-86/D-90).
- `publish.promote_or_resume` is the one seam `publish_order.py` now calls (D-83): it runs the D-68 gate first on every invocation (D-89), then classifies, then either promotes a freshly staged order or reconstructs `PromotionResult` from the durable marker rows on a committed one — without ever opening a promotion connection on resume.
- Live proof (`LivePublishOrderResumeTest`) reproduces the exact 2026-09-24 incident: run 1 (reader password unset) commits the promotion and fails closed with `reader_role_unavailable`, writing exactly one publication row whose `table_oid` equals the live table's; run 2 (password set) resumes, exits 0, writes `summary.json` with `promotion: "resumed"`, and leaves the published table's `(oid, xmin)` unchanged — `publish._promote_in_transaction` is patched to explode if reached, and never fires.
- The closed evidence vocabulary grew to 21 stages / 58 reason codes: `Stage.PUBLICATION_SUMMARY` plus `pub_generation_superseded`, `pub_generation_ambiguous`, `db_audit_read_failed`, `pub_summary_failed`, each with a distinct, secret-free hint; `evidence.ProgressEvent.publication_resumed` and `evidence._require_utc_timestamp` give the resume event a validated, UTC-normalized, fixed-microsecond timestamp contract.
