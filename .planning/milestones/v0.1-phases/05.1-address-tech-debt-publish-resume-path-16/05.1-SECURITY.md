# Phase 05.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| publish_order.py → PostgreSQL (loader login) | Loader reads vicmap_audit and pg_class and runs the one promotion transaction; the state it reads decides whether DDL runs | Catalog OIDs, marker rows; loader credential (secret) |
| vicmap_audit.publication rows → resume decision | A durable row counts as provenance only together with a matching live pg_class OID, and only when all rows form one consistent promotion | Marker rows (integrity-critical) |
| live `vicmap.*` tables → classification | Out-of-band replacements, legacy unmarked tables and re-staged runs are untrusted states the classifier must not act on | Table OID/xmin (integrity-critical) |
| publish.py → run directory / operator output | summary.json is overwritten on every resume; the promotion field, published_at and the resumed event reach the operator | Evidence scalars (must carry no DSN, password or local path) |
| publish.py → vicmap_audit (gate, validation re-read) | Failure reports must name the audit boundary so the operator applies the right fix | Failure stage/code |
| operator (superuser) → production vicmap | By-hand provisioning of the marker table and its grant | Superuser DDL (privileged, manual) |
| executor → production vicmap / planning files | Read-only grant checks, the D-88 probe, evidence text in WINDOWS.md and SUMMARY | Grant booleans, counts, commit hashes (no secrets) |
