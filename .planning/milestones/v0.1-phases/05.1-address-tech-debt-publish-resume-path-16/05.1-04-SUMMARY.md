# Phase 05.1 Plan 04: Audit-read boundary confinement + marker-privilege precheck Summary

**`assert_all_layers_validated` and `read_layer_validations` now run on the read-only audit connection so a vicmap_audit read failure is always `db_audit_read_failed`, and a PROMOTE verdict fails closed with `AuditPrivilegeDenied` before any DDL when the loader cannot write the publication marker.**

## Accomplishments

- `assert_all_layers_validated` (the D-68 gate) and `read_layer_validations` (the post-commit re-read) both moved from the promotion-mapping `_connect` onto `_connect_for_audit_read` (D-90): a connection or query failure in either now raises the closed `AuditReadFailed` (`db_audit_read_failed`), never `PromotionFailed` -- closing WINDOWS.md #16's second, pre-existing instance of the same defect class RESEARCH Pitfall 2 identified in the gate itself, and its already-fixed sibling in the post-commit read.
- `_connect` now has exactly one caller in the whole module, `_promote_in_transaction`, mechanically proven by an AST probe over every `FunctionDef` in `publish.py` -- confirming D-92's boundary that `pub_promotion_failed` can only ever come from inside the promotion transaction (`_connect`, `_promote_in_transaction`, `_record_publication`), also AST-pinned by the new `PromotionFailedBoundaryTest`.
- `classify_publication_state` now computes its verdict while its own read-only connection is still open, and on a PROMOTE verdict (and only then) runs `SELECT has_table_privilege(current_user, 'vicmap_audit.publication', 'INSERT')` on that same connection -- resolving Research Open Question 2 by checking the marker table's own grant directly rather than extending `staging.preflight_staging_privileges` (which the staging CLI never touches). A denied grant fails closed with `AuditPrivilegeDenied` before any promotion connection opens, exposing the provisioning gap via a named hint instead of only surfacing as a rolled-back `pub_promotion_failed` deep inside the transaction.
- RESUME and every fail-closed classification outcome (superseded, ambiguous, conflicted, unproven, empty) issue no `has_table_privilege` statement at all -- proven by four new fixture cases in `PublicationInsertPrivilegeTest`.
- The module docstring now states the complete D-90/D-91/D-92 failure-boundary map in one place: the promotion transaction is the only source of `pub_promotion_failed`; any vicmap_audit read gives `db_audit_read_failed`/`db_audit_privilege_denied`; a fail-closed classification gives `pub_generation_superseded`/`pub_generation_ambiguous`; the summary step gives `pub_summary_failed`; the reader proof keeps its own `db_reader_verify` codes.

## Decisions Made

See `key-decisions` in frontmatter. In summary: both audit-read call sites moved onto `_connect_for_audit_read`; the classification verdict is computed before the connection closes so the new PROMOTE-only privilege check can share it; the explicit `AuditPrivilegeDenied` raise needed its own `except` clause ahead of the generic handler since it is not a `PublishFailure`; and the pre-existing AST provenance test was narrowed to `INSERT INTO` so the new read-only `'INSERT'` privilege-type literal cannot be mistaken for a second marker writer.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Narrowed `PublicationMarkerProvenanceTest`'s INSERT-constant detection to avoid a false positive**
- **Found during:** Task 2, writing `classify_publication_state`'s `has_table_privilege(..., 'INSERT')` literal
- **Issue:** The existing `test_only_record_publication_contains_insert_among_publication_table_referrers` test (from Plan 05.1-02) flags any function that both references `PUBLICATION_TABLE` and contains a string constant whose uppercase form includes `"INSERT"`. `classify_publication_state` already references `PUBLICATION_TABLE` (for the marker-row SELECT); adding the privilege check's literal `'INSERT'` argument would make this pre-existing, exact-equality AST test wrongly flag `classify_publication_state` as a second publication-table writer alongside `_record_publication`, breaking D-88's no-backfill mechanical proof for an unrelated, read-only reason.
- **Fix:** Narrowed the match from bare `"INSERT"` to `"INSERT INTO"` -- an actual write statement always says `INSERT INTO`, while the privilege-check argument is just the bare word `'INSERT'` with no `INTO`. `_record_publication`'s own INSERT statement (`"INSERT INTO {table} ..."`) still matches unchanged.
- **Files modified:** tests/test_publish.py
- **Verification:** `tests.test_publish.PublicationMarkerProvenanceTest` still passes with both the narrowed check and the new privilege-check literal present; full suite green.
- **Committed in:** `3d0a632` (Task 2 test commit)
