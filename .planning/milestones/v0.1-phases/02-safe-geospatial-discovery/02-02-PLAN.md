<objective>
Close the Phase 1 → Phase 2 provenance gap and make Phase 2's policy reviewable in `vicmap.toml`.

Purpose: `02-RESEARCH.md` Pitfall 5 verified a real cross-phase gap — D-32 requires the manifest to record the Phase 1 message fingerprint, but `run_acquisition` only ever renders it to stdout and then discards it. The operator resolved this during planning: persist it in Phase 1. This plan does that, and gives the Phase 2 ceilings and format allowlist the same reviewable, fail-closed TOML treatment the Phase 1 policy already has.
Output: A durable `artifacts/Order_{id}.provenance.json` sidecar with an atomic writer, a reader with a typed closed failure, a provenance-only CLI mode for artifacts acquired before this existed, and validated `[extraction]`/`[discovery]` config sections.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| `vicmap.toml` → process control flow | Non-secret policy values decide extraction ceilings and the format allowlist. |
| `artifacts/Order_{id}.provenance.json` → Phase 2 | A local file that decides whether the artifact is accepted for extraction. |
| artifact bytes → `run_provenance` re-hash | A 233 MB local file streamed to derive the recorded digest. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-09 | Tampering | provenance sidecar | high | mitigate | Strict key-set, hex-shape, and order-ID validation in `read_provenance_sidecar`; any deviation is `ProvenanceUnavailable` and stops the run before extraction, so a tampered sidecar cannot smuggle an attacker-chosen expected digest past D-28 without also matching the artifact. |
| T-02-10 | Tampering | sidecar publication | medium | mitigate | Same no-overwrite `os.link` commit point as artifact publication; an existing sidecar is never silently replaced, so a completed run's provenance record is immutable. |
| T-02-11 | Denial of service | `[extraction]` ceilings | high | mitigate | Ceilings are validated as bounded positive integers before any archive is opened; a missing or non-positive ceiling is `config_invalid` rather than an unbounded default. |
| T-02-12 | Elevation of privilege | `run_dir` resolution | high | mitigate | `run_dir` is rejected when absolute, when it contains `..` or empty parts, when it resolves outside the config root, or when its final component is not the recognized `runs` name — so configuration cannot redirect extraction outside the git-ignored run root. |
| T-02-13 | Information disclosure | `--provenance-only` mode | low | accept | The mode reuses the existing memory-only Graph token path and emits only the same redacted `candidate_selected` fields; it performs no artifact download and adds no new credential surface. |
</threat_model>
