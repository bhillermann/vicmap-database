<objective>
Make the geospatial toolchain reproducible and prove one complete artifact-to-manifest path end to end.

Purpose: This phase's hardest architectural risk is that an untrusted 233 MB archive must be unpacked, read by an external GDAL-backed toolchain, and turned into an immutable contract Phases 3 and 4 depend on — without ever touching a database. Proving that whole path on one thin slice first means a dead end costs one commit, not ten.
Output: A dev shell that actually contains `pyogrio`/`pyproj`/`ogrinfo`, three checked-in geodatabase fixtures, the extended closed failure vocabulary, four new leaf modules, a guarded CLI, and one deterministic end-to-end regression.

This plan fixes two contracts every later plan builds on and must not rename:
- `ExtractionPolicy` and `DiscoveryPolicy` field names (02-02 maps `vicmap.toml` keys onto them; 02-03 and 02-04 only add validation).
- `LayerProfile` / `FieldProfile` field names (02-04 fills them, 02-05 reads `dataset_stem`/`layer_name`, 02-06 serializes them).

D-29 (`manifest.json` as the documented Phase 2 → 3 handoff) is rated **costly** in CONTEXT.md: the shape this tracer establishes is finalized by 02-06 and is referenced by the Phase 4 run summary, so changing it later touches the loader, the summary composer, and every retained manifest.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| `artifacts/Order_{id}.zip` → extraction | A 233 MB archive that arrived over the network in Phase 1 is untrusted input; its central directory is attacker-influenceable metadata. |

| geodatabase bytes → GDAL/pyogrio | Untrusted binary format parsed by a large C library. |
