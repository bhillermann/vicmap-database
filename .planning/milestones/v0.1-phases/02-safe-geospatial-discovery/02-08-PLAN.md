<objective>
Close the extraction duplicate-member bypass so recorded provenance can never describe a file that is not on disk.

Purpose: closes verification gap 1 (CR-01, GEO-01 blocked). `_validate_members` builds its D-26 aliasing guard from the raw `ZipInfo.filename` string while `_reject_unsafe_member` has already computed the resolved destination path one line later. Two members with different literal names that resolve to one path both pass. Reproduced at HEAD during this planning run: an archive of `d/f.txt` (10 bytes) and `d//f.txt` (12 bytes) extracts with no guard trip, leaving exactly one 12-byte file on disk while `ExtractionResult.members` records two entries — including one claiming `d/f.txt` is 10 bytes with a SHA-256 that matches nothing anywhere. The run reports SUCCESS, and the manifest inherits the false provenance. Silent corruption is a worse failure mode than the hard stop this phase was designed around.
Output: an aliasing guard keyed on destination identity rather than on an archive-supplied string, exclusive-create output handles so the filesystem itself is the last oracle, and an independent provenance-integrity check that would have caught this defect no matter how the guard was written.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive-supplied member names → local destination paths | Attacker- or vendor-controlled strings decide where bytes land on disk. |
| extraction result → manifest provenance | `ExtractedMember` byte counts and digests become the durable record Phase 3 and Phase 4 cite. |
| in-memory guard decisions → filesystem reality | A guard's model of "which members are the same file" must agree with the filesystem's answer. |
