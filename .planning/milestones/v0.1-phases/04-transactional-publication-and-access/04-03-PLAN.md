<objective>
Close the D-68 cross-phase handoff gap: Phase 3 today emits `LayerValidation` only as an ephemeral event, so no durable PASS record exists for the Phase 4 gate to trust. Add a driver-isolated `record_validation` writer to `vicmap_acquire/staging.py` and call it from `stage_order.py` after a successful staging run, persisting one PASS row per layer to `vicmap_audit.staging_validation` (D-69/D-70). Add a `manifest_digest` reader to `manifest.py` so the row is keyed by the exact verified digest the gate will match on.

Purpose: The publish gate (04-04) refuses to promote unless every manifest layer has a PASS row for this run's `(run_ts, manifest_digest)`. That record must be written by the phase that actually validated the data — Phase 3 — proven durable here. Re-running Phase 3 staging against the proof delivery repopulates the record.

Output: `record_validation` in `staging.py`, its call site in `stage_order.py`, `manifest_digest` in `manifest.py`, all tested (live tests skip without a server).
</objective>
